# Helper Desk (bb plugin)

Shows what sub-agents are doing while an agent works, modelled on Ben AI's Helper Desk mod.

- **Taskbar** above the composer: purple progress bar, "Tasks n/m" (to-do list) or "Agents n/m" (sub-agent batch when there is no to-do list), percentage, close button, and "Now: ..." line.
- **Orchestrator card**, pinned at the top of Live and always present: a mascot as the lead's face (3D by default, the original pixel sprites in the Pixel style) (picked from the chat's thread id, see Mascots; it walks while the lead works and blinks while it waits), "Lead · <model>", its state (Working, Waiting for you, or Needs you when an interaction is pending or the turn errored), a one-line activity ("Running install.sh", "Reading README.md", "Thinking", "Writing reply"), context used ("288k · 29%") and the estimated session cost.
- **Agent tree**: sub-agents hang under the lead on connector lines in each agent's colour. A pulse travels down on launch, a signal loops while running, and a pulse travels back up when an agent finishes, then the card hops, ticks and slides away. Nested sub-agents indent one more level. When idle, a thin dashed "No agents running · View history" row hangs under the lead.
- **Helper Desk panel** (thread right panel, opens itself once per batch): "N subagents in this chat", three tiles (Total chat cost, Subagent tokens, Time), green "Running · n" and yellow "Finished · n" bars, one card per sub-agent with a mascot in the agent's colour, tokens and time, current step, recent actions and a progress bar.
- **Auto-hide** (setting "Auto-hide finished agents", on by default; delay "Seconds to keep finished agents on screen", default 8): when every agent in a batch has finished, the cards stay with their final numbers, then slide away and the taskbar fades. A panel that opened itself closes again if you did not touch it; a panel you opened shows "No agents running · View history".
- **History tab**: a timeline of every agent batch on the current thread, newest first ("Today 14:32", the request, agents, tokens, duration, estimated cost). Each node expands to the lead line ("Lead · model · request") with that batch's agents beneath it in the same tree, each with the agent's result and "Show more". Rebuilt from the thread's event log; the parsed state is cached in plugin storage by thread and last event seq. The header button shows the lead mini-bot, plus a count while agents run, and reads "Helper Desk" when idle (opens History directly).
- **Model switches across native continuations**: when a chat moves to another model through a native continuation (for example GPT-6.1 Sol to Opus 5.5), the NavAIgate Workspace plugin keeps the new model in its own hidden session. Helper Desk treats the sessions as one conversation: the live view on the original chat follows the session that is working (else the newest continuation), the lead card reads "Switched model · GPT-6.1 Sol → Opus 5.5 · Today 23:03", and History lists every session's agent runs, each with its own lead model, with a "Switched model" marker (from, to, time) wherever the model changed. A model change inside one session is marked too. The grouping is read, never written, from the skin's public thread metadata (`navaigate-skin` / `nativeConversation: { rootThreadId, sourceThreadId, kind }` on each member; members are hidden, top-level, unarchived threads in the root's project; an archived member drops out of the chain), and each turn's model from `execution.model` on bb's `client/turn/requested` events. The skin keeps its selected session (`activeThreadId`) in its private storage, so when you select an earlier session by hand while nothing is working, Helper Desk still follows the newest one. Making that exact needs one addition on the skin's side: mirror `activeThreadId` (and the member list) into `nativeConversation` metadata on the root thread.
- **Avatars** (`mascots.tsx`, `avatars/`): nine monochrome canvas animations, ported from the 21st.dev "Set of animations" component (see `THIRD_PARTY_NOTICES.md`): Sphere Scan, Crystalline Refraction, Sonar Sweep, Helix Scanner, Interconnecting Waves, Cylindrical Analysis, Voxel Matrix Morph, Phased Array Emitter and Crystalline Cube Refraction. Every agent, sub-agent, workflow and worktree card (Live, History, Team) wears one, picked by hashing the agent's id so it keeps it across refreshes. They draw in the page's ink colour (`--hd-avatar-ink`, falling back to `--foreground`), so light and dark both read; only a running agent turns a soft blue. Working is lively, waiting and idle are calm, done and failed hold a still frame (failed fainter). The lead card wears the **NavAIgate N** (the one 3D mascot kept, see below) unless you give it an animation of its own.
- **How the avatars run** (`avatars/animations.ts`, `engine.ts`, `Avatar.tsx`, `assign.ts`): each animation is a pure function `draw(ctx, size, t, { ink, alpha })` that draws one frame in a 180-unit space scaled to `size`, so the same code serves a 24 px row and a 180 px preview, with dots thickened at small sizes. One shared `requestAnimationFrame` loop serves every visible avatar, capped at 30 frames a second. It asks for no frames while the tab is hidden, when every avatar is off screen (one `IntersectionObserver`) or held still, and with `prefers-reduced-motion` each avatar draws one still frame. Small avatars draw less often (12 fps up to 32 px, 20 fps up to 64 px, slower again in a crowd). Canvases are backed at the device pixel ratio. The ink is re-read when the theme class or colour scheme changes. There are no per-avatar timers.
- **The NavAIgate N** (`avatars/nmark.ts` draws it, `avatars/NavN.tsx` mounts it): the lead card wears the brand icon the way the NavMotion films draw it. The path is `navaigate-icon-light` from the NavMotion logo set, verbatim (the same path as the favicon), filled flat in the page ink, so it is crisp at any devicePixelRatio and follows the light and dark themes. It runs on the shared 30 fps avatar loop like every other avatar (asleep when hidden or off screen, one still frame under reduced motion). On mount it plays the film's open (a dot, then the mark grows out of it). Idle is a slow light sweep along the ribbon with long rests and a very slight breathe; working is the same sweep quicker and in the one brand blue (#2A5BFF); waiting breathes the whole mark into the blue; done and error hold the resting mark (error dimmed). While it works or waits, an orbit turns round the N: 24 evenly spaced brand-blue dots (fewer on a small canvas), a larger brighter head with a fading tail and a faint bloom, one turn in 2.6 s, eased in and out over 0.45 s (a held state keeps the loop playing just long enough for it to leave); under reduced motion it is a still ring with the head at the top. Idle, done and error draw no ring. The N is sized so its farthest point clears the ring at every size, and nothing is drawn outside the canvas. Preview: `node scripts/harness/build.mjs n2d . /tmp/hd-n/harness.html`. The older 3D N (`mascots3d/`, shader and strips) is no longer mounted by anything; it is kept only for its tests.
- **The N's pre-rendered loop** (`mascots3d/strips.generated.ts`, `scripts/build-strips.mjs`): the build captures the N's shader frames into one WebP strip per state (56 px frames; the N ignores the card colour). The strips are inlined as data URIs because the plugin build bundles only JavaScript and CSS; the module is imported on first use and a card plays a strip with a composited `steps()` transform. Regenerate with `node scripts/build-strips.mjs` (needs agent-browser and the bb toolchain's esbuild; it serves the capture page on 127.0.0.1 only).
- **Measuring**: `node scripts/harness/build.mjs anim . /tmp/hd-anim/anim.html` writes the avatar preview (the nine at 180, 96, 48 and 24 px, the agents list and the Mascots tab; `?theme=dark`, `?view=panels`, `?coach=<animation id>`) and, with `?bench=1`, prints the draw cost per animation and the shared loop's cost per tick. `node scripts/harness/build.mjs perf <helper-desk dir> /tmp/page.html` bundles forty running cards into one page, and `node scripts/harness/analyse-trace.mjs trace.json` reads a Chrome trace saved by `agent-browser trace stop`.
- **Choosing mascots** (`mascotchoice.ts`, `mascotpicker.tsx`, `mascotstab.tsx`): press the avatar on any card (Live, History, the lead, Team) to open "Choose mascot" under it, pick one of the nine from live previews, or go back to Automatic. The fourth tab, **Mascots**, sets the default set (which animations the unpicked cards rotate through, never fewer than one), shows a 180 px live preview of any of them in any state, and sets the right-hand mascot: one of the nine, or the coach with its shape (circle, pebble, squircle, capsule, triangle, hexagon, cloud, drop) and its colour (the twelve customiser colours, or the theme). The cloud in the theme colour stays the default. Choices live in this window's localStorage (`bb-plugin-helper-desk:mascots:v1`); picks left over from the old pixel and 3D mascots are dropped on load, the newest 300 card picks are kept, and every mounted card and the companion update at once.
- **Coach companion** (app-wide overlay, `companion.tsx`, brain in `companionmodel.ts`): the coach (the NavAIgate platform's cloud-shaped bot, vendored in `coach/`, bloub engine, MIT) lives on top of bb and is interested in what you are doing. His eyes follow the pointer everywhere. Rest the pointer and he wanders over to look (up and to the right of it); rush the pointer at him and he goes wide-eyed and hops away. Click or type in any text field and he flies over and perches on its top edge above the caret, sliding along as you type with a bob per key; pause and he thinks; send and his eyes roll round his head, he winks and hops. Password fields: he closes his eyes. When the chat needs you he goes to the composer with his badge and bounces. With no input for 90 seconds (and no agent working) he falls asleep in the corner and wakes up startled. He follows the chat in view (thinking while it works), never takes a click, reads only geometry (pointer and caret rectangles, never text), stops when the tab is hidden, sits still under reduced motion, and hides on phone-sized screens. Setting "Show the coach companion" (`companion`, default on).
- **Team tab**: every agent working for this chat and the git worktree each one works in. In a grouped native conversation (the NavAIgate Workspace plugin's root and its continuation and parallel members) it covers every session, so a Workflow running in the Opus continuation shows from the Sol root, and the session strip reads "GPT-6.1 Sol first -> Opus 5.5 now", with sessions running alongside listed apart. Rows: each session's lead (provider, model, state), Claude Code and Codex sub-agents, Workflow runs and their agents (phase), child bb threads, Fleet mirrors and `bb fleet start|ask|tell` jobs on another Mac (with "Open on <machine>" and, for a mirror, "Open the copy here"). Each row carries a worktree chip: folder, branch, changed files (clean or n changed) and ahead/behind its upstream, or the main checkout's branch when it has none; the full path is in the tooltip, and a Worktrees list groups them by how many agents use each. Where a worktree comes from, in order: Claude Code's worktree isolation (`worktreePath` in the agent's meta), bb's environment (child threads), else the checkout the agent's recent tool calls touch most (edits and `cd`/`git -C` count more than reads), because agents keep the session's cwd and reach worktrees by path. Workflow agents are tied to their transcripts through the run's `journal.jsonl` (labels to agent ids); Codex sub-agents through their rollout files (`~/.codex/sessions`, by the delegation's child ref). Git is only read (`--no-optional-locks`, short timeouts). CLI: `bb helper-desk team <thread-id>`. Fleet jobs are known only from the commands' own output: a started job counts as working for six hours unless its answer came back.
- **Toasts**: "Done: <agent>" when a sub-agent finishes while you are watching.
- **CLI**: `bb helper-desk show <thread-id>` (live), `bb helper-desk history <thread-id>` (past batches) and `bb helper-desk team <thread-id>` (agents and worktrees).

Data: bb thread events (delegations, background agents and the sub-agent items bb streams into the parent thread), bb's to-do list and context usage, and the local Claude Code sub-agent transcripts (read incrementally) for live tokens, model and cost. Cost is an API-equivalent estimate marked "est." unless bb reports a real figure.

Develop: `npm install --include=dev`, `npm run check`, `npm test`, read-only harnesses `HD_LIVE=http://127.0.0.1:38886 HD_THREAD=thr_x HD_OUT=/tmp/team.json npx vitest run tests/live-harness.test.ts` and `HD_TEAM=/tmp/team.json HD_HTML=/tmp/team.html npx vitest run tests/render-harness.test.tsx`, `bb plugin build`, `bb plugin reload helper-desk`.
