# NavAIgate Console 1.13.0, run a model on your own Mac from the new-chat screen, 22 November 2026

So this one is about local models, because I wanted to open a new chat, pick a model that's on my own Mac and just talk to it, without a cloud account in the middle and without setting anything up in a terminal every time, and now there's a Local orb on the new-chat screen that does exactly that. There's a step-by-step page with screenshots at https://skyremote.github.io/navaigate-console/local-models.html if you want to see it before you install.

## What changed

- **A Local orb next to Online.** Once you tick "Online or Local on the new-chat screen" in Setup, there are two orbs where the mark used to be, and Online is a chat exactly as it was before, and Local starts the chat through bb's opencode harness on a model you pick. The list comes from opencode, so it shows the models opencode lists from Ollama and LM Studio, it leaves out the models Ollama reports as coming from its cloud, and the chat gets a Local flag in the sidebar so you can filter for it. A fresh install on the Simple preset leaves that box unticked, so tick it first, and if you finished Setup before 1.13 it's ticked after the update, with Online still chosen until you pick Local.
- **It stays on your Mac.** A Local chat writes its own title on your Mac, so the first message doesn't go to bb's title service, and the line under the box says Local, the model's name and "runs on this Mac", and that's about the model and only the model, because the chat's tools, a project's own connectors, web fetches and bb's own tools can still go out to the internet the same as in any other chat. If you switch an opencode chat to another model halfway through, the line says it started Local and names the model it's on now, so it never tells you it's local when it isn't.
- **Load and Unload from the orb.** Under the orb there's a memory row that tells you whether the model is in memory, with a Load and an Unload button, and on the 48 GB Mac we tested on, a 27B Qwen model took about 18 GB in LM Studio with a 65,536-token window. If your Mac has less than 40 GB, Load won't ask LM Studio for that window, because it could run out of memory, and it tells you to load it in LM Studio with a smaller window instead.
- **A note when your skill list will make the first reply slow.** opencode puts every skill in `~/.claude/skills` and `~/.agents/skills`, up to 200, into the first prompt of every new chat, so from about 90 skills the Local orb now shows a note with your count and an estimated size, which is about 11,000 tokens plus about 155 per skill, and from about 190 skills it also tells you what happened with 200 skills on our test Mac. We only measured 0 and 200 skills, so everything in between is an estimate and it isn't a measurement of your Mac, and the note only reads and counts, so nothing opencode receives changes.
- **Claude Code on a local model, if you want to try it.** This one is experimental and it's off until you tick it in Setup, and it runs Claude Code itself on the model on your Mac. The orb checks the model first, so you only get it with a model that can call tools and runs with at least a 65,536-token window, and it starts in Accept Edits, or Full Access if that's what you choose, because at the start Approve for me checks every step with the same local model and one small file write took 16 minutes that way. A fork of that chat, or a chat it starts on Claude Code, stays on the same local model, and with the feature switched off it doesn't start at all, and its transcript is kept in its own folder, `~/.claude-local/config/projects`, away from your main Claude Code history.
- **The speed on Claude Code, honestly.** On our own bb build a new chat's first reply took about 2.5 to 4 minutes, and in our test on standard bb 0.49, with the Mac busy with other work, it took about 12 minutes, because Claude Code's first prompt there was about 25,400 tokens and the model needed more than 5 minutes to read it, and a request with no reply after 5 minutes is sent again. Follow-ups in the same sitting took 9 to 32 seconds, but a follow-up after the chat's session had closed took as long as a first reply. Any Mac that needs more than 5 minutes to read that first prompt can see the long first reply, and we haven't fixed it yet.
- **A few smaller bits.** You can give any chat a colour in the sidebar, you can drop a chat onto a folder that belongs to another project, and if you've got the MCP Manager plugin, sending `/mcp` on its own opens its page with every connector and its status, which is off until you tick it.

## What we ran on standard bb 0.49

On 22 November we installed the official bb 0.49 as a separate copy with its own data folder and its own home folder, on one 48 GB Apple Silicon Mac, and the public installer put 1.12.5 in and the same installer then updated all seven plugins in place to this release from a local copy of the repository, with nothing removed. The Console loaded and opened Setup by itself, and with the defaults there was no Claude Code switch under the Local orb and nothing was written to `~/.claude-local` until we ticked the experimental box. A Local chat through opencode with a 27B Qwen model in LM Studio listed a folder, read a file and gave the right answer, with the first output after 196 seconds and the answer after about 4 minutes, and a Local chat on Claude Code gave the right answer after about 12 minutes, with two 5-minute re-sends on the way, and its follow-up came back in 21 seconds. A fork of that chat ran on the same local model, and with the box unticked both the chat and a new fork were blocked before anything reached a model, and with the model unloaded the chat stopped with a clear error and LM Studio didn't load anything by itself.

That first test ran the release as it stood at overlay commit 5a07808, which carries the Console at 5c34de6, so it came before the skill-list note and the last text fixes.

So then we ran a second, shorter test on the exact build that ships, overlay ca24e98 with the Console at 90b5d33, and this time we did it the way most of you will meet it, so we installed 1.12.5 on a fresh copy of standard bb 0.49, finished Setup on the Simple preset, made a chat on a local model through opencode, and then updated to this release from a local copy of the repository with the installer as it ships. All seven plugins updated in place with nothing removed and no load error, Setup didn't open again, your saved Setup choices came through byte for byte, and the old chat opened with its answer still there. After the update the new-chat screen showed the Online and Local orbs with Online chosen, and Setup showed "Online or Local" ticked and the experimental Claude Code box unticked. The skill-list note showed up with the count at 120 skills, and at 200 and 260 skills it showed 200, which is opencode's limit, and it stayed away on Online and with Claude Code chosen, and the plugin, server and browser logs had no error from it. A Local chat through opencode on that final build gave the right answer again, with the first output after 208 seconds and the answer after 254 seconds, with no skills installed.

The Local chat on Claude Code, the fork rule, the block when that feature is off and the error when the model isn't loaded were run on the earlier build in the first test and not run again on the final one, and the server code behind them has only changed in its comments since. What neither test proved: an Online chat, because the test copy wasn't signed in to a Claude account; what the claude program sends over the network, because we didn't capture its traffic; why a request is dropped at 5 minutes; and anything on Windows or Linux.

## Known limits

- We tested on one Mac, a 48 GB Apple Silicon Mac. Macs with 24 to 32 GB are untested, we're not aiming at 16 GB, and nothing was run on Windows or Linux.
- Nothing is downloaded for you. You install Ollama or LM Studio and the model yourself, and INSTALL.md has the exact commands under "Local models (optional)".
- On Claude Code, a first prompt that needs more than 5 minutes to read is sent again, so any Mac that needs more than 5 minutes to read it can see a long first reply, about 12 minutes in our standard bb test with the Mac busy, and we haven't fixed that.
- On opencode, your skill list goes into every first prompt, and with 200 skills on a larger setup three test chats gave no answer in 12 minutes while that Mac was busy with other work, and the Console doesn't trim the list for you yet, so the fix today is to move the skills you don't use out of those two folders, and your other Claude Code and agent chats stop seeing them too. To count them, run `ls ~/.claude/skills ~/.agents/skills | wc -l` in a terminal, and it's a rough number, because it counts every entry in both folders.
- On the Claude Code harness there are exactly four cases where a chat marked Local can still reach your cloud account on its own: the plugin isn't loaded, or bb drops its settings after bb's 5-second limit, when the chat starts or restarts; the chat's first start is on another machine and its Local mark can't be read; a chat it started doesn't get held to the local model (for example it's more than four steps down, or it runs on Codex); or another plugin sets which claude program the chat runs before the Console does. A Local chat in opencode isn't sent to a cloud account by the Console, but a chat it starts can be, in the first, third and fourth of those cases. INSTALL.md lists them in full, together with the things you can do yourself that take a Local chat's content somewhere else, like handing it over to an online model or sharing it through a guest review link.
- bb's own model box shows a cloud model name, "Opus 5.5" in our test, on a Local chat on Claude Code, and from the second message on the sidebar and bb's record of the chat show it too, but the chat still runs on the local model, so trust the Console's label under the box, and only bb can change its own labels.
- The Cache Clock card shows cloud cache prices and a Keep warm button on Local chats too, and none of that applies to a Local chat, so don't press Keep warm on one.
- The cloud-model check reads what Ollama reports, and we haven't tried it against a real cloud model yet. If you point opencode or a runner at another machine, the Console can't tell.
- bb's plugin list still shows version 0.35.0 for the Console after the update, because bb updates it by commit, and the release number is in `RELEASE_SOURCES.json` and in these notes.
- An Online chat wasn't tried on the clean copy of standard bb, because that copy wasn't signed in to a Claude account.
- A chat you made on a local model before 1.13 has no Local mark after the update, so the sidebar counts it as Online, and only chats you start from the Local orb carry the mark.
- If you save Setup after the update, the preset name changes from "simple" to "custom", and nothing you ticked before changes.
- At 200 skills the note gives you two sizes, the estimate of about 42,000 tokens and the about 48,000 we measured with 200 skills on a larger setup, so don't be thrown when the two numbers don't match.
- The guided tour has no step for the Local orb yet.

## If you already installed

If you finished Setup on 1.12, you'll see the Online and Local orbs on the new-chat screen after the update, with Online chosen, so your chats work as before until you pick Local, and you can untick "Online or Local on the new-chat screen" in Setup if you'd rather not see them. That's exactly what we saw when we updated a test install that had finished Setup and had a chat on 1.12.5.

Run the same install line again, `curl -fsSL https://raw.githubusercontent.com/skyremote/navaigate-console/main/install.sh | bash`, and it updates the Console where it is.
